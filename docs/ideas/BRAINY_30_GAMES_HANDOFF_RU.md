# Brainy / Brainee — хэндофф 30 развивающих мини-игр

Дата: 14 ноября 2026. Аудитория: США, английский язык. Формат поставки: исходники и статические сборки на своём сервере. Дизайн исходных игр сохраняется; редизайн — отдельная следующая задача.

**Состав: ровно 15 игр из прежней тридцатки для 6–7 лет + 15 новых для ребёнка около 8 лет.** Возраст — рекомендация для старта, не проверенная норма развития. Ориентир: Grade 1 и Grade 2–3; готовность ребёнка важнее даты рождения. L1/L2/L3 ниже — предлагаемые профили Brainy, а не утверждение, что эти три уровня уже реализованы авторами.

## 2. Что передаётся и что можно запустить

- `catalog.json`: все 30 ID, источники, возраст, навыки, задачи интеграции, маршруты.
- `sources.lock.json`: зафиксированные Git-коммиты, файлы и Git blob hashes; SHA-256 архивов.
- `launch_games.py`: загрузка нужного поднабора, статический preview, экспорт на собственный сервер. Python 3.10+, только стандартная библиотека.
- `starter-content/`: три небольших английских примера для H5P; это рабочие данные для старта интеграции, **не полный банк Grade 2–3**.
- `vendor-cache/`: три точных H5P library ZIP с зависимостями. Hub URL изменяемый, поэтому сохранены копии с контрольными суммами.

Скрипт не изменяет проект тиммейта, не запускает `db:reset`, не регистрирует игры в БД и не имитирует награды/bridge. Он делает конкретный первый шаг: получает исходники/артефакты и открывает игру на своём HTTP-сервере. Кнопка запуска ещё не равна интеграции с прогрессом ребёнка.

### Быстрый старт

Распаковать весь комплект в отдельную папку, перейти в неё в терминале:

```sh
python launch_games.py list
python launch_games.py prepare mind-math
python launch_games.py serve mind-math --open
```

Другие примеры:

```sh
python launch_games.py prepare tangram-tales
python launch_games.py prepare context-clues
python launch_games.py prepare code-maze
python launch_games.py prepare all
python launch_games.py serve --port 8070 --open
```

На macOS/Linux команда интерпретатора может называться `python3`. По умолчанию файлы пишутся в `.brainy-games` текущей папки; для другого места добавлять **одинаковый** `--workspace /path/to/cache` в prepare/serve/export. Сервер привязан к `127.0.0.1`; Ctrl+C останавливает его. Загрузка требует интернета; готовая статика обслуживается локально. Сервер не является production backend.

У нас QLOBE и Sugarizer уже скачаны. Чтобы не загружать заново, можно передать `--reuse-qlobe /path/to/qlobe-kids --reuse-sugarizer /path/to/sugarizer` команде prepare. Скрипт берёт только файлы, совпадающие с зафиксированными Git-хешами. Общие файлы переиспользуются между играми. Полный набор выбранных QLOBE/Sugarizer с общей базой — примерно 270 MiB, плюс Blockly/H5P и редактируемые исходники. Это объём скачивания на сервер, не загрузка всех игр в браузер ребёнка.

Экспорт готовой статики в **новую** директорию проекта:

```sh
python launch_games.py export --to /path/to/brainee/apps/web/public/vendor-games
```

Затем при запущенном Next.js открыть `/vendor-games/` или `/vendor-games/play.html?id=mind-math`. Экспорт требует нового пути и не перезаписывает существующие каталоги. Эта preview-оболочка предназначена разработчику; в продукте её заменяет `IframeGame` с bridge.

### Четыре рецепта сборки

**Q — QLOBE.** Vanilla JS/DOM/Canvas и общие модули. Build не нужен. Сохранять `games/<id>/` и `shared/`, а также общие `js/css/assets`, поскольку пути относительные. Скрипт получает их из pinned commit. Дизайнерская версия Pattern Train из предыдущей задачи не используется.

**S — Sugarizer.** Выбранные активности поставляются как браузерная статика с локальными библиотеками. Не выполнять корневой `npm start`: он запускает Electron. Сохранить структуру `activities/<Name>.activity/` и общие root libs. Preview устанавливает English и локальный профиль без Sugarizer Server. Лаунчер в своей копии исправляет Reflection (RequireJS paths + внешние Google Fonts) и FoodChain (внешний resource prefix → локальный). Это совместимость, а не редизайн. Journal/Share/Stop и Sugarizer home при продуктовой интеграции заменить host-эквивалентами.

**H — H5P.** Player `h5p-standalone@3.8.2` скачивается как npm tarball; `dist` обслуживается локально. Нужны одновременно player, библиотеки типа задания со всеми `preloadedDependencies`, `h5p.json`, `content/content.json` и локальные медиа. Скрипт собирает их автоматически из зафиксированных архивов. Одного GitHub-репозитория H5P content type недостаточно для запуска. Редактируемый исходник каждой библиотеки скачивается отдельно в `editable-sources`. Его commit новее runtime-пакета: не смешивать файлы этих версий. Для редизайна собрать выбранную source-версию и её совместимые зависимости отдельной задачей.

**B — Blockly.** Для быстрого запуска скрипт получает официальный English offline ZIP с ветки `offline`, pinned commit `2768f123085854bcf972081d3b222c2d7ffa4158`. Это готовый артефакт, отдельный от редактируемого source commit `5d2ff6f39207f7ed31e3d11ba1de277c85efe4c2`, который тоже скачивается. Открывается `blockly-games/en/maze.html?lang=en&level=3`. Полная пересборка исходника: upstream `make deps` → `make maze`/`make games`; старый Makefile использует SVN-доступ к GitHub и неприкреплённые загрузки, поэтому этот путь требует обновления загрузчика зависимостей и здесь не заявлен проверенным. Для немедленного просмотра использовать offline artifact. [Официальная инструкция](https://github.com/blockly-games/blockly-games/wiki/Offline).

## 3. Приоритеты и учебная политика

В первой волне интеграции: **Tangram Tales, Sentence Workshop, Secret Message Lab, Rhythm Copycat, Target Number Lab, Mirror Grid, Context Clues, Paragraph Detective, Code the Maze, Reading Detective**. Они дают разные действия: построение, язык, память, вычисление, отражение, чтение и программирование. Все 30 остаются в объёме MVP; этот порядок помогает тиммейту отладить разные адаптеры.

Не включены из прежней тридцатки простые counting cups, addition/subtraction до 6, базовая обводка букв и сходные вводные механики. У сохранённых игр QLOBE исходная аудитория преимущественно 4–6/5–6 лет. Поэтому **повышение сложности в карточках — обязательная работа**, а не переименование возрастного бейджа. Свободные лаборатории и творчество помечены отдельно: без миссий они не дают валидируемого результата.

Навыки используют реальные enum проекта: `reading`, `speech`, `logic`, `attention`, `memory`, `motor`. Предложение 70% main / 30% secondary согласуется с моделью проекта, но не является научно измеренным эффектом игры. Перенос этих весов в изменение тела Брейни выполняет `packages/core`. `responsibility` не выдаётся за клики; речь не измеряется автоматически по записи микрофона. Для `learningFromMistakes` нужны реальные повторные попытки; `longGame` требует наблюдений между сессиями, а не длины уровня.

Ориентиры по программе США: [Grade 2: +/− и задачи](https://www.thecorestandards.org/Math/Content/2/OA/), [Grade 3: дроби](https://www.thecorestandards.org/Math/Content/3/NF/), [Grade 2: понимание прочитанного](https://www.thecorestandards.org/ELA-Literacy/RL/2/), [Grade 2: словарь, контекст и письмо](https://www.thecorestandards.org/ELA-Literacy/L/2/). Это ориентиры содержания, не утверждение об одинаковой программе всех штатов. Симметрия, программирование и астрономия здесь также представлены как enrichment.

**Оценка доработок:** S — настройка/небольшой адаптер; M — новая схема заданий или несколько изменений логики; L — новая система миссий поверх свободного инструмента. Это относительная оценка, без обещания часов; общий bridge и весь банк контента в неё не включены.

## 5. Карточки: 15 из прежней подборки

### 01. Sentence Workshop — `tiny-sentence-workshop`

**Возраст / класс:** 6–7; Grade 1; L3 — переход к Grade 2. **Предмет:** ELA: reading & writing. **Навыки:** `reading` 70% + `logic` 30%. **Доработка:** S.

**Почему в подборке:** Синтаксис и понимание предложения, а не узнавание отдельной буквы.

**Что есть в исходнике:** Расставить слова по порядку, прочитать предложение слева направо и найти соответствующую сцену. Все три действия представлены в исходных режимах.

**Открытый код:** [конкретная игра / библиотека](https://github.com/kaigani/qlobe-kids/tree/60967634e6cc313c41a5aa8067bed9f0f616176c/games/tiny-sentence-workshop). Commit: `60967634e6cc313c41a5aa8067bed9f0f616176c`.

**Запуск:** рецепт Q из раздела 2.

```sh
python launch_games.py prepare tiny-sentence-workshop
python launch_games.py serve tiny-sentence-workshop --open
```

**Статический entry:** `vendor/qlobe/games/tiny-sentence-workshop/index.html`. Preview URL: `/vendor-games/play.html?id=tiny-sentence-workshop` после экспорта.

**Файлы для разработчика:** `config.json`, `game.json`, `js/main.js`. Пути относительны каталогу игры/библиотеки из ссылки выше.

**Сложность для целевого возраста:**

- **L1:** 4–5 слов с одной иллюстрацией; без готового порядка.
- **L2:** 5–7 слов, два правдоподобных отвлекающих слова.
- **L3:** Два коротких предложения: восстановить порядок и выбрать причинное продолжение.

**Пример задания:** The small dog sleeps under the table. → выбрать сцену, где собака под столом, а не на нём.

**Конкретные доработки:** Банк минимум 24 предложений: субъект/действие/объект, затем adjective и preposition. Хранить допустимые порядки и связанные сцены; не объявлять любой альтернативный грамматический порядок ошибкой. Добавить заглавную букву и пунктуацию как отдельный шаг.

**Раунд / событие результата:** Один раунд — полностью собранное и сопоставленное со сценой предложение; mistakes считать по Check, а не по каждому переносу слова.

**Английский и контент:** Интерфейс и исходные аудиоклипы English. Новый контент — en-US; запись фразы обновлять вместе с текстом.

**Статус проверки:** В предыдущем аудите открывалась локально в iframe, выполнялись отдельные действия. Это не полное прохождение и не проверка предложенных L1–L3.

**Приёмка этой игры:** запускается с English, выполняется указанный пример, принимаются все допустимые ответы, одна исправленная задача даёт одну correction; повторный Check не дублирует завершение. Для открытого творчества применяется practice/rubric, а не фиктивный correct. Проверить самостоятельный выход и отсутствие продолжающегося звука после удаления iframe.

### 02. Word Train: Blend & Build — `blend-train`

**Возраст / класс:** 6–7; Grade 1; L3 — переход к Grade 2. **Предмет:** ELA: phonics. **Навыки:** `reading` 70% + `attention` 30%. **Доработка:** M.

**Почему в подборке:** Оставляем ради фонемного синтеза; простые CVC не должны быть единственным содержанием для первоклассника.

**Что есть в исходнике:** Ребенок соединяет вагоны со звуками и слышит, как получается короткое английское слово. Готовая база: два режима, onset-rime и сборка по фонемам.

**Открытый код:** [конкретная игра / библиотека](https://github.com/kaigani/qlobe-kids/tree/60967634e6cc313c41a5aa8067bed9f0f616176c/games/blend-train). Commit: `60967634e6cc313c41a5aa8067bed9f0f616176c`.

**Запуск:** рецепт Q из раздела 2.

```sh
python launch_games.py prepare blend-train
python launch_games.py serve blend-train --open
```

**Статический entry:** `vendor/qlobe/games/blend-train/index.html`. Preview URL: `/vendor-games/play.html?id=blend-train` после экспорта.

**Файлы для разработчика:** `config.json`, `game.json`. Пути относительны каталогу игры/библиотеки из ссылки выше.

**Сложность для целевого возраста:**

- **L1:** CVC: собрать слово по картинке без написанного образца.
- **L2:** CCVC/CVCC: frog, clap, nest; 1–2 лишних графемы.
- **L3:** Диграфы sh/ch/th и сравнение ship/shop; звук и написание размечены отдельно.

**Пример задания:** frog = /f/ /r/ /ɒ/ /g/; для американской озвучки проверить целевую гласную и не переносить британскую запись автоматически.

**Конкретные доработки:** Добавить минимум 36 слов с массивами graphemes/phonemes и локальными записями фонем и целых слов. Не разбивать sh на два звука. Обновлять картинку, слово, транскрипцию и MP3 вместе.

**Раунд / событие результата:** Раунд — одно собранное слово после явной проверки; прослушивание звука не является ошибкой.

**Открытый код:** [конкретная игра / библиотека](https://github.com/llaske/sugarizer/tree/60ccdbcb004de1a706749c7314edfa0d160288b4/activities/Memorize.activity). Commit: `60ccdbcb004de1a706749c7314edfa0d160288b4`.

**Запуск:** рецепт S из раздела 2.

```sh
python launch_games.py prepare meaning-memory
python launch_games.py serve meaning-memory --open
```

**Статический entry:** `vendor/sugarizer/activities/Memorize.activity/index.html`. Preview URL: `/vendor-games/play.html?id=meaning-memory` после экспорта.

**Файлы для разработчика:** `js/memorize-app.js`, `js/sample-ressources.js`, `js/palettes/template-palette.js`. Пути относительны каталогу игры/библиотеки из ссылки выше.

**Сложность для целевого возраста:**

- **L1:** Шесть пар word ↔ clear definition с предварительным знакомством.
- **L2:** Восемь пар synonyms/antonyms; тип отношения указан.
- **L3:** Десять пар word ↔ sentence with a blank; одинаковые слова не повторяются.

**Пример задания:** enormous ↔ very large; whisper ↔ speak very quietly.

**Конкретные доработки:** Создать 12 словарных наборов. Пара определяется pairId, не совпадением строки. Не смешивать synonyms и antonyms без маркировки. Промах памяти не равен незнанию слова — хранить две метрики раздельно.

**Раунд / событие результата:** Обработчик совпадения пары в memorize-app.js. Для session выбрать один board = round либо каждую пару = round и согласовать roundsPerSession; не менять трактовку между уровнями одной записи каталога.

**Английский и контент:** Штатный набор букв заменить английскими смысловыми парами; локальные аудиозаписи необязательны.

**Статус проверки:** Ранее проверено открытие локальной активности и несколько действий; полного прохождения всех режимов не было.

**Приёмка этой игры:** запускается с English, выполняется указанный пример, принимаются все допустимые ответы, одна исправленная задача даёт одну correction; повторный Check не дублирует завершение. Для открытого творчества применяется practice/rubric, а не фиктивный correct. Проверить самостоятельный выход и отсутствие продолжающегося звука после удаления iframe.

## 7. Пошаговая интеграция с архитектурой Brainee

### 7.1. Сначала запуск, потом учёт прогресса

1. Внешние исходники держать вне monorepo приложения. Получать закреплённый build artifact с checksum, как предусмотрено Path C в `docs/dev/games.md`.
2. Статику разместить под `/vendor-games/` для инженерного просмотра. Все пути должны работать и в подкаталоге; не использовать file://.
3. Реализовать T-29 по контракту проекта: `packages/game-bridge`, `IframeGame`, ветку `GameHost`. В документации указан готовый образец `../game-store-planning`, но его нет в данном публичном checkout. Тиммейт должен предоставить этот соседний проект либо реализовать и проверить оговорённый протокол. Этот комплект не притворяется его заменой.
4. Добавить runtime metadata в DB / manifest, загрузку embedded catalog в `getGame` и `/lab`. Сейчас `getGame` ищет только две React-игры.
5. Добавить английскую локаль host UI: загрузка, ошибка, выход, result, retry, названия игр. `GameText` не содержит строк всех внешних игр: их контент и locale передаются отдельно.
6. Для каждой игры реализовать адаптер наблюдаемых попыток и конца сессии. Запускать в детском каталоге только после conformance QA.

### 7.2. Контракт результата: сохраняем существующий

```ts
type GameResult = {
  gameId: string;
  level: number;
  rounds: number;
  mistakes: number;
  corrections: number;
  durationMs: number;
};
type RoundEvent = { correct: boolean; afterMistake: boolean };
```

`rounds` должен точно совпадать с `roundsPerSession` этой записи каталога. Для направленных игр разумный новый профиль — 4 конечные задачи; исходные 3 раунда QLOBE, 10 попыток FractionBounce и одно поле Memorize не нормализуются автоматически. Либо адаптировать сессию к четырём задачам, либо зарегистрировать фактическое число. Для Dictation starter содержит три предложения — нельзя сообщать rounds=4.

`mistakes` — неудачные проверки ответа; `corrections` — число завершённых раундов, в которых была хотя бы одна ошибка. Это не проценты точности H5P, не число перетаскиваний и не итоговый счёт Sugarizer. Сохранять `hadMistake[roundId]`; после правильного ответа один раз отправить `onRound({correct:true, afterMistake:hadMistake})`. Ошибочный ответ может дать `onRound({correct:false, afterMistake:false})` для обратной связи; после финала игнорировать дальнейшие ответы.

Сервер проверяет целые неотрицательные счётчики, corrections ≤ rounds и mistakes, соответствие issued game/level и длительность относительно выданной сессии. Нельзя отправлять `rounds` с незавершёнными задачами после выхода. Для редакторов/песочниц без валидатора использовать practice без `finishLearningSession`. Если ребёнок ошибся и вышел до исправления, это exit/stop, не искусственно успешный результат.

### 7.3. Последовательность жизненного цикла

1. Host получает issued session через `POST /api/sessions/start`.
2. В init передаёт gameId, level, seed, locale=`en-US`, ограничения сессии. Локальные query-параметры preview не являются авторизацией.
3. Игра отправляет ready только после загрузки данных и обязательных ассетов; ошибку загрузки нельзя считать completed.
4. Bridge принимает события только от ожидаемого frame/MessageChannel, по nonce и контракту. Повторные eventId отбрасываются; ограничения размера/частоты — по существующему дизайну проекта.
5. Host собирает/принимает GameResult и вызывает уже существующий `finish` в LearningProvider. Игра не вызывает reward API напрямую.
6. При потере ответа повторяется тот же sessionId/result, используется штатное восстановление pending finish.
7. Exit, pause, unmount останавливают аудио, requestAnimationFrame, timers и microphone tracks. Простой iframe `load` не является игровым ready или finish.

**Нельзя использовать QLOBE_DEBUG.winRound(), H5P showSolution или автоклик как доказательство прохождения.** Debug API допустим для диагностики; production adapter должен слушать реальные игровые проверки.

## 8. Контент, готовность и минимальная приёмка

Полный контентный минимум для выбранной игры: 3 профиля сложности, минимум 4 неповторяющиеся сессии на профиль, все ответные ключи и допустимые альтернативы, English instructions, объяснение после ошибки и metadata contentVersion. Для творческих игр — сценарии и рубрики вместо выдуманного ключа. Все задания из карточек, кроме явно названных upstream features и starter-файлов, ещё предстоит добавить.

До детского каталога тиммейту проверить:

- Chromium и WebKit: начало → ошибка → исправление → конец → выход; ширины 360/390 и iPad landscape.
- Реальные touch и keyboard interactions; targets не меньше 48px, отсутствие блокирования ответа незавершённой озвучкой.
- Один finish при двойном клике, retry и remount; для соседних iframe нет пересечения сообщений.
- Ноль runtime-запросов к чужим доменам; локальные изображения, MP3, fonts, WASM и библиотеки.
- Reduced motion, кнопка выключения звука, отсутствие бесконечного автоперехода, рейтингов детей и таймерного давления.
- Соответствие locale: US English не гарантируется одним `lang=en`; проверить записанный голос, spelling, единицы и AM/PM.
- Научные задания проверяет редактор содержания. Игровые показатели не подавать как медицинскую диагностику или доказанный перенос навыков.

## 9. Честные границы этой поставки

Репозиторий Brainee прочитан на конкретном commit; состав исходной тридцатки сопоставлен с новой подборкой. QLOBE/Sugarizer использованы с результатами предыдущего локального launch-аудита, а не объявлены полностью протестированными продуктами. Три H5P starter и лаунчер подготовлены как ускоритель интеграции. По просьбе ускорить выдачу полный повторный browser/build/dependency QA этого комплекта не проводился. Проблемные места отражены в карточках; скрипт не является гарантией полного прохождения каждой игры.

Сборка приложения тиммейта, изменение его БД, установка production bridge, полный английский банк заданий и редизайн не выполнялись. Все материалы для продолжения находятся в этом комплекте; ссылки на открытый код даны для каждой игры.
